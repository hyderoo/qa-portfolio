## Charter

SauceDemo ships accounts with deliberately seeded faults. Explore
`problem_user` and `locked_out_user` against the `standard_user` reference
and file anything that deviates.

## What was covered

- Login with valid, locked-out, empty and wrong credentials
- Inventory content, image integrity, all four sort options
- Add-to-cart for every product, remove, badge behavior, persistence across
  navigation
- Full checkout: info form, overview, finish, confirmation

## Findings (filed as bug reports)

- BUG-001: all product images are the same placeholder (`problem_user`)
- BUG-002: 3 of 6 products cannot be added to the cart (`problem_user`)
- BUG-003: sorting has no effect, all options (`problem_user`)
- BUG-004: Last Name input writes into First Name, checkout blocked
  (`problem_user`)

## Method notes

- Every finding was reproduced at least twice before filing.
- Sorting was verified from a fresh page load per option, after observing
  that repeated programmatic changes to the sort control do not reliably
  re-render on this app (test-method artifact, not a product bug).
- `locked_out_user` behaves per spec: login rejected with "Epic sadface:
  Sorry, this user has been locked out."
- `standard_user` passed every scenario executed - evidence:
  [../screenshots/standard-user-inventory.png](../screenshots/standard-user-inventory.png)
